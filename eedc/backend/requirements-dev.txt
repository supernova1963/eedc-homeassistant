# Test-Runner — alle 31 Akzeptanz-Tests sind als top-level `async def test_*`
# geschrieben und werden via `asyncio_mode = "auto"` automatisch geladen.
pytest>=7.4.0
pytest-asyncio>=0.23.0

# Starlette ≥ 1.7 TestClient — `starlette.testclient` (über `fastapi.testclient`) lädt zuerst `httpx2` und
# fällt sonst mit einer StarletteDeprecationWarning auf `httpx` zurück (je xdist-Prozess eine Warnung in der
# Summenzeile). Untergrenze wie Starlettes eigenes Extra `full` (`httpx2>=2.0.0`). Nur Testseite: das Produkt
# nutzt weiter `httpx` aus requirements.txt; nicht im Lock (das Lock löst nur requirements.txt auf).
httpx2>=2.0.0,<3

# Parallelisierung — der Gate-Befehl in CLAUDE.md ruft `-n 3` auf, damit MUSS das
# Plugin hier stehen: ein Werkzeug, das im dokumentierten Gate vorkommt, gehört in
# die Datei, auf die das Gate zum Installieren verweist (sonst bricht es auf einem
# frischen Klon). Messung 24.08. auf 4 Kernen: 126 s → 47–62 s, vier Läufe grün.
# Die Test-DB ist in-memory je Test, die Worker stören sich nicht.
pytest-xdist>=3.8.0

# ⛔ `pytest-cov` steht bewusst NICHT hier (Entscheid 24.08.). Kein Gate benutzt es;
# in dieser Datei würde es nur die Install-Zeit jedes CI-Laufs verlängern, und eine
# Abhängigkeit, auf die nichts zeigt, driftet unbemerkt mit. Für einen einmaligen
# Messlauf: `VIRTUAL_ENV=eedc/backend/venv uv pip install pytest-cov`
# (die venv hat weder `pip` noch `ensurepip`), dann

# Obergrenze, weil eine neue Minor neue Regeln oder Fixes bringen kann; Anheben = einmal messen.
ruff>=0.17.0,<0.18

# Kognitive Komplexität (SonarSource-Metrik) für den Wächter backend/tests/test_kognitive_komplexitaet.py —
